# SKILL — Using the Venom Design System

Instructions for anyone (human or agent) building Venom Router surfaces from this package.

## Package

`@venom/design-system` is a private, local, SemVer-versioned React + TypeScript + Vite package (`package.json`). It is not published to any registry. Two supported consumption modes — pick one, don't invent a third:

1. **Workspace/local package dependency** — from the consuming repo, `"@venom/design-system": "file:../path/to/Design_System"` (or an npm/pnpm workspace entry) in `package.json`, then `import { Button, Meter } from "@venom/design-system"` (or the narrower `/tokens`, `/themes`, `/density`, `/icons`, `/primitives`, `/domain`, `/tailwind` subpaths) and `import "@venom/design-system/styles.css"`.
2. **Deterministic handoff copy** — run `npm run build` in this package, then copy `dist/`, `assets/`, `themes/`, `tokens/*.css`, `tokens/*.json`, `icons/icons.css`, `css/`, and `styles.css` into the consuming repo's vendored-design-system directory exactly as listed in `package.json`'s `files` array. `validation/handoff-contract.md` has the full procedure.

Do not load this package from a CDN, a git submodule, or a loose unmanaged file copy — those are not supported.

## Consume

1. **Link the one stylesheet:** `<link rel="stylesheet" href="styles.css">` (relative to the package root), or `import "@venom/design-system/styles.css"` from a bundler. It pulls in fonts, primitive/semantic/component/density tokens, all three themes, base type styles, core + domain component CSS, and the icon classes (vendored locally in `assets/icons/` — no CDN).
2. **Set theme and density on the root element:** `data-theme="venom-dark" | "venom-light" | "venom-hc"` (dark is the `:root` default) and `data-density="comfortable" | "compact"` — drive them with the `ThemeSwitcher`/`DensityToggle` components, applied via `applyTheme`/`applyDensity` (`themes`/`density` entry points) or a direct `setAttribute` call. Persist the choice server-side (`PUT /settings`), never in browser storage — neither component persists anything itself.
3. **Use the React components** in `components/**/<Name>.tsx` (prop contracts in the sibling `.d.ts` — generated by `npm run build:declarations`, never hand-edited — usage snippets in `.prompt.md`). They are presentational: feed them view models, never wire them to API clients. Every specimen page (`storybook/`, `states/`, component cards, `ui_kits/venom-console/`) is a real Vite entry (`*.entry.tsx`) — there is no in-browser Babel transpilation and no CDN dependency; `npm run dev` / `npm run build:explorer` / `npm run preview` are the only supported ways to run them.
4. **Style only with tokens.** Every visual value is `var(--…)` from `tokens/*.css` / `themes/*.css`. Look up real names in those files (or `tokens/tokens.ts`); a raw hex/rgb in UI code fails gate 5.
5. **Tailwind apps:** use the generated preset — `import { venomTailwindPreset } from "@venom/design-system/tailwind"` and set `presets: [venomTailwindPreset]` in `tailwind.config`. It is compiled from the same authored `tokens/*.json` as the CSS/TS outputs and its values are `var(--…)` references, so utilities re-resolve under `data-theme`/`data-density` at runtime. Never hand-author or duplicate a token → Tailwind mapping in the consuming app.

## Compose

- Follow `patterns/patterns.md` for the app shell, page anatomy, forms, feedback, density, and every domain flow (enrollment, reauth, reveal, discovery, quota, traces, keys, backup/restore). The 17 reference surfaces live in `ui_kits/venom-console/` — fork a screen from `screens-*.jsx` rather than starting blank.
- Copy for labels, errors, confirmations: `patterns/content-style.md`. Canonical vocabulary only; typed error codes verbatim in mono.
- State rendering: never hand-map a domain state to a color. Use the domain components (`AccountStatus`, `FundingBadge`, `CertificationStateBadge`, `ReservationStateBadge`, `TierBadge`, …) — they encode `states/state-matrix.md`. Key invariants: unknown ≠ failure (dashed + circle-help); unknown funding ≠ free; unknown quota ≠ unlimited (hatched meter, never a number); routable = certified ∧ all required truths supported (show the conjunction); `reconciliation_pending`/`unknown_consumption` never look neutral; tiers colored only via `tier.*` tokens; only `venom/lite|pro|max` exist.

## Extend

- **New token:** edit the authored JSON in `tokens/` (all three semantic files for a semantic token), then run `validation/build-tokens.cjs` (`buildVenomTokens(io)`) to regenerate the CSS/TS/Tailwind outputs. Never edit generated files (GENERATED header). A new non-color semantic token additionally needs an explicit mapping in the Tailwind emitter — the build fails loudly rather than dropping it.
- **New theme:** one new complete semantic JSON + a registry entry in `validation/build-tokens.cjs`; the build fails on any divergence from the canonical 93-token set.
- **New component:** `<Name>.tsx` + `.d.ts` + `.prompt.md` + a state in its group's `*.card.html`, tokens only, keyboard + ARIA behavior per `accessibility/contract.md`. Gates 5/12 fail otherwise.
- **New icon:** extend the pinned Lucide set in `icons/icons.css` and, for domain concepts, `DOMAIN_ICON_MAP` in `components/icons/Icon.tsx` + `icons/icon-map.md`. Never hand-draw glyphs.

## Validate (run after any change)

`npm run validate` (`node scripts/validate.js`) runs every fast mechanical gate from a real Node process against the real filesystem — no undocumented `io` object to supply yourself — prints a readable summary, writes `validation/report.json`, regenerates `validation/report.md` from the actual run, and exits non-zero if any gate fails:
1. `buildVenomTokens` — schema, completeness, reference legality (`validation/build-tokens.cjs`).
2. `checkVenomContrast` — the AA/AAA matrix (`validation/check-contrast.cjs`).
3. `checkVenomGuardrails` — raw-color lint, terminology, secret canary, icon map, state coverage, story/contract coverage, forbidden-CDN scan, required-component presence (`validation/check-guardrails.cjs`).
4. Type check (`tsc -p tsconfig.json --noEmit`) over the package's public entry points and components.
5. Declaration generation, twice: `components/**/*.tsx` -> sibling `.d.ts` (`tsconfig.declarations.json`), and the package entry points -> `dist/types` (`tsconfig.build.json`). Drift is structurally impossible: the checked-in `.d.ts` is tsc's own output.
6. Explorer production build (`vite build --config vite.explorer.config.ts`) — a broken import/export fails this step outright, not silently.
7. Library build (`vite build`) — the shipped `dist/*.mjs` / `dist/*.cjs`. `dist/` is removed and rebuilt from scratch inside the run, so a stale chunk can never mask a broken build; the temporary export-check probe is removed afterwards.
8. Package export completeness — every `dist/*.mjs` entry point is imported and asserted non-empty.
9. Handoff manifest (`validation/check-handoff.cjs` against `validation/handoff-manifest.json`) — every top-level entry classified, canonical sources + generated-required artifacts present, no stale legacy duplicate (`src/*.d.ts`, `*.jsx`, `*.entry.d.ts`, browser-Babel runtime), transients covered by `.gitignore`, `src/` free of component implementation logic.

`npm run test:a11y` / `npm run test:visual` (Playwright + axe-core, and the screenshot-diff suite — see `tests/`) are separate, slower, browser-driven commands; run them explicitly — they are not bundled into `npm run validate`.

Do not weaken a gate to make it pass, and do not hand-edit `validation/report.md` or `validation/report.json` — both are generated by `scripts/validate.js`.

## Repository map (what is authored vs generated)

Full table with regeneration commands: `README.md` § "Repository map". The short version:

| Path | Role | Authored/Generated |
|---|---|---|
| `components/` | canonical component source (+ generated sibling `.d.ts`) | Authored |
| `src/` | public entry points / barrels only — never component logic | Authored |
| `tokens/tokens.*.json` | token source of truth | Authored |
| `tokens/*.css` (except `base.css`/`fonts.css`), `tokens/tokens.ts`, `tokens/tailwind-theme.ts`, `themes/*.css` | compiled token outputs | Generated (committed) — `npm run validate` |
| `assets/icons/`, `icons/icons.css` | vendored icon set | Generated (committed) — `npm run vendor:icons` |
| `css/`, `styles.css`, `foundations/`, `states/`, `patterns/`, `storybook/`, `ui_kits/`, `accessibility/`, `tests/`, `scripts/`, `validation/*.cjs` | docs, examples, tests, gates | Authored |
| `tests/visual/*-snapshots/` | visual baselines — update only on intended change | Baseline (committed) |
| `validation/report.*`, `theme-token-manifest.json` | gate evidence | Generated (committed) — `npm run validate` |
| `dist/`, `dist-explorer/`, `test-results/`, `node_modules/` | build output / transients / deps | Generated/transient — **never** in the handoff set (`.gitignore`) |

Never hand-edit a generated file; change its authored source and regenerate. The handoff set is
machine-defined in `validation/handoff-manifest.json` and enforced by the validate handoff gate.

## Maintain

- Tokens are API: reviewed, changelogged, renames ship with a codemod (see `validation/handoff-contract.md`).
- Offline packaging: fonts fall back to the documented system stack (`tokens/fonts.css`) and Lucide icons are vendored (`assets/icons/`, regenerated by `npm run vendor:icons`) — no runtime network access anywhere in this package, including the explorer.
- Explorer: `npm run dev` (live) or `npm run build:explorer && npm run preview` (production-preview) renders every card, state matrix, and the 17-surface console across theme × density — the fastest full visual review.
